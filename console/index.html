Overview & user flow

Module 1 · Discovery of the mini-bank estate

Cryptographic inventory

The same hybrid engine as page 2 (rules + ML classifier + crypto verification) reads the mini-bank's code and nginx configs. Certificates, keys and dependency files are parsed exactly, and one real TLS handshake is made to every running service. Each row is a finding with file:line or endpoint evidence. These findings drive the risk scores, the QpiAI plan and the migration.

Hybrid detection engine · rules + ML classifier + crypto verification

Detection engine: trained on real bank code

The classifier is trained and tested on 11 real bank and fintech repositories (read-only, never run). They are training and validation data only: the engine that scans our mini-bank on page 1 is this same engine. Re-validating takes several minutes; the last results are shown below.

Try it: paste any code

Paste Java, Go, Python, Rust, JS, Scala, nginx or OpenSSL config. Every candidate line shows the decision trail: which rule fired, the ML probability, whether the algorithm was verified, its severity and banking context.
